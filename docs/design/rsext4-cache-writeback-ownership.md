# rsext4 缓存回写所有权

## 问题与证据

OrangePi 5 Plus 上的 StarryOS 自编译在约 190 秒、93/246 个编译单元时失败。文件系统尚有约 33 GiB 可用空间，但日志连续报告
`jbd2:handle_credits` 的 `no space is available`，随后 Cargo 无法删除两个对象文件。Linux 恢复启动后的 `fsck` 又修复了强制复位遗留的不一致。

现场文件并不大，目录也只有少量 HTree 叶节点。真正的资源耗尽是运行中事务的 journal credit，而不是磁盘块空间。原缓存达到软上限时，会在一次无关的 cache miss 中直接写回脏 inode、位图或元数据块；这些隐藏写入扩大了当前事务的修改集合，并使 unlink 等本来额度固定的操作承担缓存淘汰的额外 journal 消耗。

## 用户、目标与非目标

直接用户是使用 `rsext4` 的 StarryOS 文件系统路径，首要负载是板端用 `tg-xtask` 编译 `arceos-helloworld`。成功条件如下：

- cache miss 和容量回收不写回无关的脏 inode、位图或元数据块；
- 脏元数据只由拥有 journal、错误传播和提交边界的显式路径写回；
- 独立设备模式下的普通文件数据仍保持有界批量回写，避免无限占用内存；
- 元数据与普通数据不能以不同类型别名同一个缓存块；
- 原有 Linux 镜像兼容性、unlink/reap 生命周期和失败回滚行为不退化。

本改动不改变 ext4 磁盘格式，不增加 unlink 的 journal credit，不调整 StarryOS 系统调用语义，也不把强制复位后的 `fsck` 当成正常一致性机制。性能提升幅度只能由相同镜像、相同板卡和相同完整编译负载实测确认。

## Linux 对齐

Linux 把脏元数据的生命周期绑定到拥有它的事务和写回路径，而不是让通用缓存回收随意发起写入：

- `try_to_free_buffers` 在页内 buffer 仍为 dirty、writeback 或 referenced 时拒绝回收；
- JBD2 在释放 buffer 前检查 journal 所有权，不释放仍由事务管理的 `buffer_jbd`；
- ext4 unlink 先定位目录项，再以固定的 ext4 数据事务额度启动 handle，修改目录项、父 inode、orphan 状态和目标 inode。其额度不应被无关缓存淘汰偷偷扩大。

这里对齐的是所有权与失败边界，不照搬 Linux 的页缓存、writeback worker 或锁实现。

## 方案

### inode 与位图缓存

容量回收只淘汰 clean 条目，不执行设备 I/O。若缓存中的候选项全部为 dirty，则允许暂时超过软上限，由拥有完整上下文的显式 flush 或事务提交路径处理。

这会让短时内存占用高于配置的软上限，但不会把一次查询或分配 cache miss 变成不可见的元数据写入。软上限仍控制 clean 项回收，不是持久化承诺。

### 数据块缓存

每个脏块记录 `FileData` 或 `Metadata` 类型：

- `Metadata` 只能在显式 flush/flush-all 中以 metadata I/O 写回，缓存压力下允许暂时溢出；
- `FileData` 在独立设备模式下保留原有的有界、连续批量回写；共享下层缓存模式不保留重复的脏普通数据；
- 同一块在未清洁前不得从一种类型改为另一种类型，否则返回结构化损坏错误；
- 批量写回只能合并块号连续且类型相同的快照；写入前后同时校验块号、代际和类型，陈旧快照不得清除当前脏状态。

### 错误与回滚

缓存压力不再产生元数据 I/O，因此也不会在无关调用点吞掉或重标记 journal 错误。显式写回失败保留脏状态，继续返回原始设备或 journal 错误。该方案没有磁盘格式迁移；若需回滚，应先在可工作的内核上完成同步和干净卸载，再切回旧实现。

## 替代方案

| 方案 | 结论 |
| --- | --- |
| 增大 unlink 或所有事务的 journal credit | 不采用。掩盖隐藏写回，增加日志占用，且无法给无关淘汰建立正确上界。 |
| 缓存满时同步所有脏项 | 不采用。延长持锁/事务路径并混合不同操作的失败所有权。 |
| 所有脏项永久不回写 | 不采用。普通文件数据可能无限增长；仅元数据在压力下延迟到显式所有者。 |
| clean-only 元数据回收，加上有类型的普通数据回写 | 采用。保持事务边界，并保留独立设备下的数据缓存内存上界。 |

## 验证与板端准入

回归测试首先证明旧实现会在无关 cache miss 中写回脏 inode/块，再证明新实现保持脏项且不产生设备写入。组件测试还覆盖元数据软上限溢出、普通数据有界淘汰、同类型连续批量写入、metadata I/O 路由、活动 journal handle 失败回滚，以及 Linux HTree 镜像上的删除与重命名。

代码完成后必须依次通过差异格式检查、rustfmt 检查和 `cargo xtask clippy --package rsext4`，随后才能运行测试。实体板卡验证仅在有人可恢复电源时进行，并使用 Linux 启动项自动恢复、20 分钟 watchdog 和启动前后 `fsck` 闭环。板端验收必须跑完整 `arceos-helloworld` 编译，记录总时间、编译单元进度、CPU 利用率、journal/块设备热点和任何原始错误；未完成该测试前不得宣称板端问题已解决或给出性能提升比例。
