# 完整缓存块区间读取候选

## 状态与证据

M 持锁者窗口正常结束后执行 RED：6 项中前两项失败、4 项通过，退出 101。
旧实现完整命中仍读取一次设备，设备 EIO 时返回 Err(EIO) 而非缓存数据。
实施完整命中快路径后同一 6 项全部 GREEN；候选 N 已完成 QEMU 窗口，
相同根盘起点的基线复测 M2 也已完成，见下方原始指标与限制。

L 全量 block-read-sync 栈累计 365252419344 ns，其中经过 read_inode_data_into
的栈为 203172739056 ns。该入口已经用 extent 初始化区间查询及 read_run 合并
连续物理块，单次上限 1 MiB；上层页缓存已有最大 32 页预读，不能重复建设。
但 DataBlockCache::read_run 总是先读 backing，再用命中缓存覆盖，完全命中
时仍发生无用 I/O。上述时间包含真正缺失和命中区间，未测得可消除部分的比例，
不能将整个 203 秒当作候选收益。

## 边界与替代方案

基于当前 affddc3fecec02b31df94573063e4840433c9ebe 工作树。已有 get_or_load
支持缓存命中无 I/O；read_run 的脏缓存覆盖已由单元测试验证，所需能力属于
DataBlockCache 而非 Starry syscall 或驱动。MOSS 的锁外准备方法不能直接替代
rsext4 事务/缓存一致性设计；本候选只考虑删除已有缓存能够完全提供的读取。

保持现状不引入复杂度但保留无用 I/O。逐块读只会破坏已有批量能力；拆分部分
命中的区间可以减少更多读，但扩大算法和错误路径。优先考虑整段完全命中的
窄快路径：在同一 cache guard 内确认全部命中、复制并更新 LRU/generation；
缺任意块时保持原来连续读取及读后覆盖，锁不得跨设备 I/O。缓存容量、写回、
事务、设备 flush、文件长度、EOF/稀疏区域解释均不改动。

生产实现复用私有 overlay_run 统一缓存字节与 LRU/generation 更新；完整命中
检查和复制之间不释放 guard，缺失时显式释放 guard 后才调用设备。未新增
公共接口、依赖、unsafe、锁顺序或持久化格式。data_block.rs 已超过 800 行，
本次保持其单一数据块缓存职责，不混入大范围搬迁；新回归独立放在 tests/。

## 验证门槛

新增 tests/data_read_run.rs 直接调用生产 DataBlockCache/Jbd2Dev：全部命中
零读、设备读 EIO 时仍可完全由缓存提供数据、部分命中保留批量和脏覆盖、
缺失块 EIO 传播、命中更新 LRU/generation、短目标缓冲先报错。前两项应在
旧实现上确定性失败，再实施快路径并通过相同测试。随后执行 rsext4 全套、
fmt/clippy、真实 ext4 适配层/fsck 与独立固定 600 秒 QEMU 窗口。

只有整机进度、CPU 活跃和读取/持锁分布支持，才能称编译速度改善；减少
一个 helper 的 I/O 不是完整构建加速比，也不授权移除持久化屏障。
